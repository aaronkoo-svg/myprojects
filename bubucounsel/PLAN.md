# bubucounsel 계획

> 부부·연인이 메신저에서 다툰 대화를 캡처해 올리면, AI가 대화 흐름을 읽고
> 누가 어떤 말을 잘못했는지, 어떻게 풀고 어떻게 말하면 좋은지 알려 주는 토스 미니앱.

- 디자인 규칙: [`DESIGN.md`](./DESIGN.md)
- 조사 기준일: 2026-11-17 (토스 정책은 수시로 바뀌므로 출시 직전에 다시 확인)

## 1. 대상과 핵심 가치

- **대상**: 배우자·연인과 메신저로 다툰 직후, "내가 잘못한 건가?"가 궁금한 사람.
- **핵심 가치**: 제3자의 차분한 시선 + 지금 바로 보낼 수 있는 문장.
- **차별점**: 판정에서 끝나지 않고 → 기록(패턴) → 실전 연습(게임)으로 이어진다.

## 2. 기능 범위

### 1단계 — MVP: 대화 분석 (출시 목표)

| 기능 | 내용 |
| --- | --- |
| 스크린샷 올리기 | 앨범에서 최대 5장 선택. 순서 바꾸기, 삭제. |
| 화자 확인 | AI가 읽은 대화를 말풍선으로 다시 보여 주고 "오른쪽이 나"를 확인받는다. |
| 판정 | 한 줄 요약 + 책임 비율(예: 나 40 · 상대 60) + 그렇게 본 이유. |
| 발화별 짚기 | 문제가 된 말에 표시: 잘한 말 / 아쉬운 말 / 상처 주는 말, 각각 이유 한 줄. |
| 해결 가이드 | 지금 할 일 3단계 (예: 사과할 지점 → 상대 감정 인정 → 요청). |
| 이렇게 말해 보세요 | 바로 복사해 보낼 수 있는 문장 2~3개 (부드럽게 / 솔직하게 / 짧게). |
| 공유 | 결과 요약 카드를 `intoss://` 링크로 공유. |

### 2단계 — 기록장

- 분석할 때마다 "상대가 잘못한 점"과 "내가 잘못한 점"을 항목으로 저장.
- 주제별(돈·집안일·말투·시댁/처가·연락 등)로 묶어 반복 패턴을 보여 준다.
- 월간 요약: 가장 자주 부딪히는 주제, 나아진 점.

### 3단계 — 실전 연습 (게임)

- 실제로 다퉜던 대화를 무대로, AI가 상대 역할을 맡아 다시 대화해 본다.
- 법정 심리극 형식의 **자체 디자인**: 상대의 말에서 감정·모순을 짚고, 응답 카드를 골라 "관계 게이지"를 올린다.
- 끝나면 점수와 함께 "실제로는 이렇게 말했어요 ↔ 이번엔 이렇게 말했어요" 비교.
- 특정 게임(역전재판 등)의 캐릭터·연출·효과음·화면 구성은 가져오지 않고, 장르의 재미(추리·반박)만 참고한다.

## 3. 화면 흐름 (1단계)

```
홈 ─ [대화 캡처 올리기] ─ 앨범 선택 ─ 미리보기·순서 ─ 분석 중
                                                        │
        기록 탭 ◀─ 저장 ─ 결과(요약→발화→해결→문장) ◀─ 화자 확인
```

1. **홈**: 큰 제목 + 업로드 카드 하나 + 최근 분석 2건. AI 사용 고지는 업로드 카드 아래 한 줄.
2. **미리보기**: 썸네일 가로 스크롤, 하단 CTA `분석하기`.
3. **분석 중**: 단계 문구가 바뀌는 대기 화면 (5~15초 예상).
4. **화자 확인**: 말풍선으로 재구성, "나"가 맞는지 한 번 탭.
5. **결과**: 한 화면 세로 스크롤 — 요약 → 발화별 짚기 → 해결 가이드 → 추천 문장. 하단 CTA `문장 복사하기`.
6. **탭바**(토스 플로팅 형태): 홈 · 기록 · 연습. 2·3단계 전에는 탭을 숨기고 홈만 둔다.

## 4. 기술 구성

| 영역 | 선택 | 이유 |
| --- | --- | --- |
| 앱 | Vite + React 18 + TypeScript, **CSR 단일 페이지** | 토스 미니앱은 SSR 금지, CSR/SSG만 허용 |
| 토스 SDK | `@apps-in-toss/web-framework` 3.x (현재 3.10.0) | WebView 미니앱 공식 SDK. `npx ait init` → `apps-in-toss.config.ts` |
| UI | 자체 컴포넌트(`DESIGN.md`) + 필요한 곳만 TDS(`@toss/tds-mobile`) | 비게임은 TDS가 필수가 아님. 내비게이션 바·탭바 형태만 토스 규칙을 따름 |
| 글꼴 | Pretendard Variable (OFL, 자체 호스팅) | 무료, SF Pro 계열 인상 |
| 사진 | `fetchAlbumItems({ types:['PHOTO'], maxCount:5, base64:true })` | 권한 `photos: read`. 토스앱 5.261.0 이상 |
| 사용자 식별 | `User.getAnonymousKey()` | 로그인·서버 연동·사업자 등록 없이 사용자별 고정 키 |
| 기기 저장 | SDK `Storage` | 최근 분석, 설정 |
| 백엔드 | 서버리스 함수 1개 + DB (Supabase 권장) | AI 키는 서버에만. 토스 문서에 Supabase 연동 가이드가 있음 |
| AI | Claude API (이미지 입력) | 스크린샷 읽기 + 분석을 한 번에. 응답은 JSON 스키마로 고정 |
| 배포 | `npm run build`(`vite build && ait build`) → `npx ait deploy` | `.ait` 번들 업로드 → QR 테스트 → 콘솔에서 검토 요청 |

```
bubucounsel/
├─ app/                 # 미니앱 (Vite + React)
│  ├─ src/screens/      # Home, Preview, Analyzing, Confirm, Result
│  ├─ src/components/   # Button, Card, Bubble, AiBadge, TabBar
│  ├─ src/lib/          # toss SDK 래퍼, api 클라이언트
│  └─ apps-in-toss.config.ts
├─ server/              # 분석 API (서버리스 함수)
├─ DESIGN.md
└─ PLAN.md
```

- 브라우저에서도 개발할 수 있게 SDK 호출은 `lib/toss.ts` 한 곳에 모으고, 토스앱 밖에서는 파일 선택창 등으로 대체한다. (SDK 3.x는 샌드박스 앱을 지원하지 않아 브라우저 개발 + QR 실기기 테스트로 진행)
- 서버 CORS 허용 Origin: `https://<appName>.apps.tossmini.com`, `https://<appName>.private-apps.tossmini.com`.

## 5. 토스 출시 대응

검수에서 반려되는 항목을 설계 단계에서 막는다.

| 요건 | 대응 |
| --- | --- |
| 생성형 AI **사전 고지 + 결과 표시** (위반 시 과태료 최대 3,000만 원) | 첫 업로드 전 고지 문구, 모든 결과 카드에 `AI 분석` 배지 |
| 라이트 모드만 | 다크 테마 없음 |
| 토스 내비게이션 바 사용, 자체 뒤로가기와 중복 금지 | 자체 헤더 없음. 첫 화면에서 뒤로가기 = 종료 |
| 안드로이드 시스템 백버튼 동작 | 라우터 히스토리와 연동 |
| 핀치 줌 비활성화 | WebView 속성 설정 |
| 진입 즉시 바텀시트 금지, 나갈 길 보장 | 고지·권한 안내는 인라인, 권한은 버튼을 눌렀을 때 요청 |
| 권한 거부해도 나머지 기능 동작 | 거부 시 안내 + 설정 열기 버튼, 앱은 계속 사용 가능 |
| 로그인은 토스 로그인만 | 1단계는 로그인 없이 익명 식별키 |
| 디지털 상품 결제는 인앱 결제만, 광고는 앱인토스 광고만 | 외부 결제·광고 SDK 사용 안 함 |
| 외부 링크·자사 앱 유도 금지 | 외부 이동 없음 (긴급 상담 전화번호 안내는 법정·공공기관 안내로 허용 범위) |
| HTTPS/WSS만, `eval` 금지, 외부 도메인 렌더링 금지 | 정적 번들 + HTTPS API |
| 민감 정보 암호화 저장 | DB 암호화, 원본 이미지는 저장하지 않음 |
| SDK 호출 과다 금지 (10초당 1,000건) | 호출 래퍼에서 중복·재시도 제한 |
| 번들 100MB 이하 | 글꼴 서브셋, 이미지 최소화 |
| 문구에 비속어·과한 유행어 금지 | 해요체 문구 가이드 |

**출시 불가 카테고리 확인**: 의료(비대면 진료·병원 연결)·금융·투자·정치 등이 금지 목록에 있고, 부부 대화 코칭은 목록에 없다. 다만 "의료·심리 치료"로 읽히면 위험하므로 **'상담/치료/진단' 대신 '대화 코칭·가이드'** 로 표현하고, 전문 상담을 대신하지 않는다는 문구를 넣는다. 앱 이름(국문)도 이 기준으로 정한다.

## 6. 개인정보와 안전

이 서비스에서 가장 조심할 부분이다.

- **제3자 대화**: 캡처에는 배우자의 말과 이름·프로필이 들어 있다.
  - 원본 이미지는 분석 직후 서버에서 **즉시 폐기**, 저장하지 않는다.
  - 저장하는 것은 분석 결과 요약뿐이고, 이름은 "나/상대"로 바꿔 저장한다.
  - 업로드 전에 "상대방 대화가 포함돼요. 분석 후 이미지는 바로 지워져요"를 알린다.
  - 사용자가 기록을 전부 지울 수 있는 버튼을 둔다.
  - 개인정보 처리방침 필요 (출시 전 법률 검토 권장).
- **위험 신호**: 폭력·협박·자해 암시가 보이면 누가 잘못했는지 판정을 멈추고 안전 안내(여성긴급전화 1366, 자살예방상담 109 등)를 먼저 보여 준다.
- **판정의 한계**: 캡처된 일부 대화만으로 판단한다는 점을 결과에 표시한다. 책임 비율은 "이 대화 안에서"로 한정한다.
- **기록장의 부작용**: "상대 잘못 모으기"는 재미 요소지만 원망을 키우는 도구가 될 수 있다. 그래서 상대 항목과 **내 항목을 함께** 쌓고, 화면의 초점을 "누가 더 잘못했나"가 아니라 "우리가 자주 부딪히는 주제"에 둔다. 기록을 법적 증거로 쓰라고 안내하지 않는다.
- **연령**: 성인 대상 주제이므로 `User.getDeclaredAgeRange`로 미성년자 이용 제한을 검토한다.

## 7. 수익화

| 방식 | 조건 | 계획 |
| --- | --- | --- |
| 인앱 광고(보상형) | 사업자 등록 없이 시작 가능 (수익 5,000원 초과 시 등록 필요) | 1단계: 하루 무료 1회, 추가 분석은 광고 시청 |
| 인앱 결제 | **사업자 등록 필수**. 수수료: 앱마켓 15%(매출 늘면 30%) + 토스 5% | 2~3단계: 분석권 묶음, 연습 모드 이용권 |
| 토스 로그인 | 사업자 등록 필수 | 기기 변경 시 결제 내역 유지가 필요해지는 시점에 도입 |

AI 호출 비용이 분석 1회마다 발생하므로, 무료 횟수 제한은 처음부터 서버에서 건다.

## 9. 정해야 할 것

1. **사업자 등록 여부** — 없으면 1단계는 광고만, 인앱 결제·토스 로그인은 뒤로.
2. **판정 수위** — 책임 비율(40:60)까지 숫자로 보여 줄지, "주로 이 지점이 문제"처럼 말로만 할지. (기본안: 숫자 표시 + "이 대화 안에서" 한정 문구)
3. **앱 이름(국문)** — 콘솔 등록명. '상담' 단어를 피한 후보: 부부코치, 말다툼 코치, 우리싸움 해설 등.
4. **백엔드** — 기본안은 Supabase(Edge Function + DB). 다른 선호가 있으면 변경.
