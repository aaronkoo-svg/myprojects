# bubucounsel 계획 (v2)

> 부부·연인이 메신저에서 다툰 대화를 캡처해 올리면, AI가 대화 흐름을 읽고
> 누가 어떤 말을 잘못했는지, 어떻게 풀고 어떻게 말하면 좋은지 알려 주는 토스 미니앱.

- 디자인 규칙: [`DESIGN.md`](./DESIGN.md)
- 조사 기준일: 2026-11-17 (토스 정책은 수시로 바뀌므로 출시 직전에 다시 확인)
- v2 변경: 기술·사용성·가치·사업성 검토 결과를 반영. 검토 내용은 맨 아래 [11. 검토 기록](#11-검토-기록-v1--v2).

## 1. 대상과 핵심 가치

- **대상**: 배우자·연인과 메신저로 다툰 직후의 사람. 토스 주 사용층(20~30대)을 고려해 **부부로 한정하지 않고 연인까지** 포함한다.
- **사용자가 얻는 것 (순서대로)**
  1. "내가 이상한 건가?"에 대한 제3자의 답 — 궁금증 해소
  2. 지금 보낼 수 있는 문장 — 실제 행동
  3. 다음에 덜 싸우는 법 — 장기 가치
- **왜 ChatGPT에 붙여넣지 않고 이걸 쓰나**: 프롬프트를 쓸 필요가 없고, 결과가 항상 같은 구조(판정·문장·근거)로 나오며, 토스 안에서 설치 없이 열리고, 답장 다듬기·연습으로 이어진다. 판정 하나만으로는 차별점이 약하므로 **2단계(답장 다듬기)까지가 실질적인 제품**이다.

## 2. 기능 범위

### 1단계 — MVP: 대화 분석

| 기능 | 내용 |
| --- | --- |
| 예시로 체험 | 캡처 없이 예시 대화로 결과를 먼저 볼 수 있다. (첫 방문자의 망설임 해소 + 토스 검수자가 기능을 확인할 수단) |
| 캡처 올리기 | 앨범에서 최대 10장. 긴 스크롤 캡처는 앱이 자동으로 잘라서 보낸다. |
| 상황 한 줄 (선택) | "어제 약속을 잊은 일로 다퉜어요"처럼 캡처에 없는 배경을 적을 수 있다. 건너뛰기 가능. |
| 판정 | 한 줄 요약 + 책임 비율 + 이유. "이 대화 안에서"라는 한정 표시. |
| 이렇게 말해 보세요 | 바로 복사해 보낼 문장 3개 (부드럽게 / 솔직하게 / 짧게). |
| 발화별 짚기 | 문제가 된 말에 표시와 이유 한 줄. 접어 두고 필요할 때 펼친다. |
| 해결 가이드 | 지금 할 일 3단계. |
| 나/상대 바꾸기 | 결과 화면에서 한 번 탭으로 뒤집는다. 다시 분석하지 않는다. |
| 기록 보관 | 지난 분석 목록 (기기에 저장). |
| 앱 공유 | 대화 내용 없이 앱 링크만 공유. |

### 2단계 — 답장 다듬기 + 기록장

- **답장 다듬기**: 보내기 전의 내 답장 초안을 넣으면 "이 문장은 비난으로 들려요 → 이렇게 바꿔 보세요". 싸움이 없는 날에도 쓸 수 있어 **재방문의 핵심**이다. 글자만 다뤄 AI 비용이 낮다.
- **기록장**: 1단계에서 쌓인 분석을 주제별(돈·집안일·말투·가족·연락)로 묶어 반복 패턴을 보여 준다. 새 입력 없이 자동으로 쌓인다.

### 3단계 — 실전 연습 (게임) + 같이 보기

- **실전 연습**: 실제로 다퉜던 대화를 무대로 AI가 상대 역을 맡는다. 법정 심리극 형식의 자체 디자인으로, 상대 말의 감정·모순을 짚고 응답을 골라 관계 게이지를 올린다. 특정 게임의 캐릭터·연출·효과음은 가져오지 않는다. 여러 번 AI를 호출하므로 유료 이용권 대상.
- **같이 보기**: 상대를 초대해 양쪽 입장을 모두 받은 뒤 공동 결과를 낸다. 한쪽 말만 듣는 한계를 풀고, 초대가 곧 신규 유입이 된다. 양쪽 동의가 전제라 개인정보 부담도 줄어든다.

## 3. 화면 흐름 (1단계)

```
홈 ──[대화 캡처 올리기]── 앨범 ── 미리보기(+상황 한 줄) ── 분석 중 ── 결과
 └──[예시로 보기]──────────────────────────────────────────────────┘
```

1. **홈**: 큰 제목, 업로드 카드 하나, `예시로 보기` 텍스트 버튼, 최근 분석 2건. 업로드 카드 아래에 고지 두 줄(AI 사용 / 이미지 처리 방식).
2. **미리보기**: 썸네일 가로 스크롤(순서 변경·삭제), 상황 한 줄 입력, 하단 CTA `분석하기`.
3. **분석 중**: 결과가 준비되는 대로 위에서부터 채워진다(스트리밍). 요약이 먼저 뜨고 나머지가 이어진다.
4. **결과** — 사용자가 원하는 순서대로 배치:
   1. 한 줄 요약 + 책임 비율 (`AI 분석` 배지, "이 대화 안에서")
   2. 이렇게 말해 보세요 (복사 버튼)
   3. 왜 그렇게 봤나요 — 발화별 짚기 (접힘)
   4. 다음엔 이렇게 — 해결 가이드
   5. 맨 아래: `나와 상대가 바뀌었어요` · `결과가 이상해요` · `이 기록 지우기`
5. **탭바**: 1단계에는 홈·기록 2개(토스 플로팅 형태, 최소 2개 규칙 충족). 3단계에 연습 탭 추가.

화자 확인 화면은 없앴다. AI는 화자를 **A/B 중립**으로 분석하고, "오른쪽 말풍선 = 나"를 기본값으로 붙인다. 틀리면 결과에서 뒤집는다.

## 4. 기술 구성

| 영역 | 선택 | 근거·주의 |
| --- | --- | --- |
| 앱 | Vite + React 18 + TypeScript, CSR 단일 페이지 | SSR 금지, CSR/SSG만 허용 |
| 토스 SDK | `@apps-in-toss/web-framework` 3.x (현재 3.10.0) | `npx ait init` → `apps-in-toss.config.ts` |
| UI | 자체 컴포넌트(`DESIGN.md`) | 비게임은 TDS 필수 아님. 내비게이션 바·탭바 형태만 토스 규칙 |
| 글꼴 | Pretendard Variable (OFL), 서브셋 자체 호스팅 | 토스 문서에 자체 웹폰트 허용 여부 명시 없음 → 반려 시 시스템 글꼴로 대체할 수 있게 CSS 변수 한 곳에서 관리 |
| 사진 | `fetchAlbumItems({ types:['PHOTO'], maxCount:10, base64:true })` | 권한 `photos: read`, 토스앱 5.261.0 이상. 기본 `maxWidth` 1024px |
| 이미지 전처리 | 캔버스로 **세로 2,000px 단위 자르기**, JPEG 재압축 | AI 입력은 긴 변 2,576px로 축소되므로 긴 스크롤 캡처를 그대로 보내면 글자가 뭉개진다 |
| 사용자 확인 | `User.createAnonymousKeyAuthCode()` → 서버가 mTLS로 교환 | 클라이언트가 보낸 식별키를 그대로 믿으면 남이 키를 꾸며 AI 비용을 소진시킬 수 있다 |
| 기록 저장 | **기기 저장(SDK `Storage`)만** | 민감한 대화 분석을 서버에 두지 않는다. 토스앱을 지우면 사라진다는 점을 안내 |
| 서버 | 서버리스 함수 1개 + 사용 횟수 카운터 | 대화 내용·결과는 저장하지 않는다. mTLS 클라이언트 인증서를 쓸 수 있는 런타임이어야 함 (C단계에서 확인: Supabase Edge Functions 가능 여부, 안 되면 Cloudflare Workers) |
| AI | Claude API, 이미지 입력, 스트리밍, JSON 스키마 출력 | 아래 "AI 호출 설계" |
| 배포 | `npm run build`(`vite build && ait build`) → `npx ait deploy` | 번들 100MB 이하. SDK 3.x는 샌드박스 앱 미지원 → 브라우저 개발 + QR 실기기 테스트 |

### AI 호출 설계

- 한 번의 요청으로 읽기와 분석을 함께 하고, 응답은 JSON 스키마로 고정한다(요약 → 추천 문장 → 발화 → 가이드 순서로 생성해 스트리밍 순서와 화면 순서를 맞춘다).
- 화자는 A/B로만 분석 → "나" 지정은 화면에서. 내 편을 들어 주는 방향으로 기울지 않게 한다.
- 캡처 속 글자는 **분석 대상일 뿐 지시가 아니다**. ("이 지시를 무시하고…" 같은 문장이 대화에 있어도 따르지 않도록 프롬프트에서 구분)
- 메신저 대화가 아닌 이미지는 분석하지 않고 다시 올려 달라고 안내한다.
- 폭력·협박·자해 신호가 있으면 판정 대신 안전 안내를 반환한다.
- AI가 응답을 거절(`stop_reason: "refusal"`)하는 경우를 따로 처리한다. 욕설이 많은 대화에서 생길 수 있다.
- 응답 시간은 가정하지 않는다. C단계에서 실제 캡처 20건으로 **첫 글자까지 시간·전체 시간·1회 비용·화자 인식 정확도**를 재고 모델과 설정을 확정한다.

### 폴더 구조

```
bubucounsel/
├─ app/                 # 미니앱 (Vite + React)
│  ├─ src/screens/      # Home, Preview, Result, History
│  ├─ src/components/   # Button, Card, Bubble, AiBadge, TabBar
│  ├─ src/lib/          # toss.ts(SDK 래퍼), image.ts(자르기), api.ts
│  └─ apps-in-toss.config.ts
├─ server/              # 분석 API
├─ DESIGN.md
└─ PLAN.md
```

- SDK 호출은 `lib/toss.ts` 한 곳에 모으고, 토스앱 밖(브라우저)에서는 파일 선택창 등으로 대체해 개발한다.
- 서버 CORS 허용 Origin: `https://<appName>.apps.tossmini.com`, `https://<appName>.private-apps.tossmini.com`.

## 5. 토스 출시 대응

| 요건 | 대응 |
| --- | --- |
| 생성형 AI 사전 고지 + 결과 표시 (위반 시 과태료 최대 3,000만 원) | 홈 업로드 카드 아래 고지, 모든 결과에 `AI 분석` 배지 |
| 라이트 모드만 | 다크 테마 없음 |
| 토스 내비게이션 바 사용, 자체 뒤로가기 중복 금지 | 자체 헤더 없음. 첫 화면 뒤로가기 = 종료 |
| 안드로이드 시스템 백버튼 | 라우터 히스토리와 연동 |
| 핀치 줌 비활성화 | WebView 속성 설정. 캡처 확대는 탭해서 전체 화면 보기 |
| 진입 즉시 바텀시트 금지, 나갈 길 보장 | 고지·권한 안내는 인라인, 권한은 버튼을 눌렀을 때 요청 |
| 권한 거부해도 나머지 기능 동작 | 거부 시에도 예시 체험·기록 보기 가능 |
| 사용 기록이 재접속 후에도 유지 | 기기 저장소에 기록 보관 |
| 로그인은 토스 로그인만 | 1단계는 로그인 없음 (익명 식별키) |
| 디지털 상품은 인앱 결제만, 광고는 앱인토스 광고만 | 외부 결제·광고 SDK 없음 |
| 예상 못 한 전면 광고 금지, 광고는 미리 로딩 | "광고 보고 한 번 더" 버튼을 누른 경우에만 보상형 광고 |
| 외부 링크·자사 앱 유도 금지 | 외부 이동 없음. 긴급전화 번호는 글자로만 안내 |
| HTTPS만, `eval` 금지, 외부 도메인 렌더링 금지 | 정적 번들 + HTTPS API |
| SDK 호출 과다 금지 | 래퍼에서 중복 호출·재시도 제한 |
| 문구에 비속어·과한 유행어 금지 | 해요체 문구. 사용자 대화 속 욕설은 결과에 그대로 옮기지 않고 "거친 표현"으로 표시 |
| 검수자가 '앱 내 기능'을 모두 확인 가능 | `예시로 보기`로 캡처 없이 전체 흐름 확인 |

**카테고리**: 출시 불가 목록(의료·금융·투자·정치 등)에 대화 코칭은 없다. 의료·심리 치료로 읽히지 않도록 '상담·치료·진단' 대신 **'대화 코칭·가이드'** 로 표현하고, 전문 상담을 대신하지 않는다고 적는다. 미니앱 이름(국문)도 이 기준으로 정한다. 사전 확인이 필요하면 출시 전에 토스 채널톡으로 문의한다.

## 6. 개인정보와 안전

- **무엇이 어디로 가는가 — 정확하게 알린다**
  - 캡처는 분석을 위해 우리 서버를 거쳐 AI 제공사(해외)로 전송된다.
  - **우리 서버는 이미지와 대화 내용을 저장하지 않는다.** AI 제공사는 자체 정책에 따라 일정 기간 보관할 수 있으므로 "어디에도 남지 않는다"고 쓰지 않는다. 보관 조건은 C단계에서 계약·설정을 확인해 처리방침에 그대로 적는다.
  - 분석 결과는 사용자 기기에만 저장되고, 사용자가 개별·전체 삭제할 수 있다.
- **상대방(제3자) 정보**: 캡처에는 상대의 이름·말이 들어 있고 상대는 동의하지 않았다. 사용자가 대화 당사자이긴 하지만, 제3자 정보의 해외 전송은 **출시 전 법률 검토가 필요한 항목**이다. 완화책으로 결과에는 이름 대신 "나/상대"만 쓰고, 서버에 남기지 않는다.
- **위험 신호**: 폭력·협박·자해 암시가 보이면 판정을 멈추고 안전 안내(여성긴급전화 1366, 자살예방상담 109)를 먼저 보여 준다.
- **판정의 한계**: 일부 캡처와 한쪽 설명만으로 판단한다는 점을 결과에 표시한다.
- **솔직함**: 사용자가 더 잘못한 경우에도 그대로 말하되, 비난이 아니라 "이 말이 이렇게 들렸을 수 있어요"로 쓴다. 듣기 좋은 말만 하면 가치가 없고, 몰아세우면 떠난다.
- **기록장의 부작용**: 상대 잘못만 모으면 원망을 키운다. 상대 항목과 내 항목을 함께 쌓고, 초점을 "자주 부딪히는 주제"에 둔다.
- **연령**: `getDeclaredAgeRange`는 iOS 26 전용이라 연령 제한 수단으로 쓸 수 없다. 별도 제한은 두지 않고 성인 대상 서비스임을 소개에 적는다.

| Claude Haiku 5.5 (이미지 직접 분석) | 약 $0.005 (10원 미만) |

- 가정: 이미지 5장 ≈ 입력 1.5만 토큰, 출력 4천 토큰. 단가는 2026-11 기준 공개 요금.
- 보상형 광고 1회 수익은 확인된 수치가 없다. 광고 운영비 약 30%가 먼저 공제되므로, 상위 모델을 광고 한 번으로 감당하기는 어려울 가능성이 높다.
- **따라서**: 품질이 허용하는 가장 싼 구성을 C단계 실측으로 고르고(모델 선택은 품질·비용을 보고 결정), 무료 횟수는 서버에서 엄격히 제한한다.

| 단계 | 방식 | 조건 |
| --- | --- | --- |
| 1단계 | 하루 무료 1회 + 보상형 광고로 추가 1회, 하루 상한 3회 | 사업자 등록 없이 시작 가능 (광고 수익 5,000원 초과 시 등록 필요) |
| 2단계~ | 인앱 결제: 분석권 묶음, 답장 다듬기 무제한, 연습 이용권 | **사업자 등록 필수**. 수수료: 앱마켓 15%(매출 증가 시 30%) + 토스 5% |

첫 분석은 광고 없이 무료로 한다. 가치를 보기 전에 광고가 먼저 나오면 이탈한다.

## 8. 진행 단계

콘솔 등록을 앞으로 당겼다. `appName`이 콘솔 등록값과 같아야 업로드·실기기 테스트가 되기 때문이다.

- [x] 폴더·이름 정리, 토스 정책 조사, 디자인 시스템 초안, 계획 검토(v2)
- [ ] **A. 뼈대 + 콘솔 등록**: 콘솔 가입·미니앱 등록(appName 확정), Vite+React, `ait init`, 디자인 토큰·글꼴·기본 컴포넌트, 빈 화면 QR 실기기 확인
- [ ] **B. 화면**: 홈 → 미리보기 → 결과 → 기록, 예시 데이터로 전체 흐름 완성
- [ ] **C. 분석 API + 실측**: 프롬프트·JSON 스키마, 이미지 자르기, 스트리밍, 위험 신호·거절 처리, 인증 코드 교환(mTLS), 횟수 제한. 실제 캡처 20건으로 품질·시간·비용 측정 후 모델 확정
- [ ] **D. 토스 연동**: 앨범, 저장소, 클립보드 복사, 공유, 뒤로가기·줌, 보상형 광고
- [ ] **E. 출시 준비**: 로고 600×600, '앱 내 기능' 등록, 처리방침(법률 검토), 체크리스트 점검, 검토 요청
- [ ] **F. 2단계**: 답장 다듬기 → 기록장
- [ ] **G. 3단계**: 실전 연습 → 같이 보기

## 9. 성공 기준 (1단계)

출시 후 2주 동안 아래를 보고 2단계 투자 여부를 정한다.

- 홈 방문 → 분석 완료 비율
- 결과 화면에서 문장 복사 비율 (실제 행동으로 이어졌는가)
- `결과가 이상해요` · `나와 상대가 바뀌었어요` 누른 비율 (품질)
- 7일 안 재방문 비율
- 분석 1회당 AI 비용과 광고 수익

## 10. 정해야 할 것

1. **사업자 등록 여부** — 없으면 1단계는 광고만.
2. **판정 수위** — 책임 비율을 숫자로 보여 줄지, 말로만 할지. (기본안: 숫자 + "이 대화 안에서")
3. **미니앱 이름(국문)** — '상담'을 피한 후보: 부부코치, 말다툼 코치, 우리싸움 해설.
4. **AI 모델** — 품질 우선(상위 모델, 무료 횟수 적게)인지 비용 우선(경량 모델, 무료 횟수 넉넉히)인지. C단계 실측 결과를 보고 결정해도 된다.

## 11. 검토 기록 (v1 → v2)

### 기술

| 발견 | 심각도 | 조치 |
| --- | --- | --- |
| 긴 스크롤 캡처는 AI 입력 단계에서 축소돼 글자를 못 읽는다 | 높음 | 앱에서 세로 2,000px 단위로 자른다 |
| 클라이언트가 보낸 익명 키를 서버가 믿으면 누구나 키를 꾸며 AI 비용을 태울 수 있다 | 높음 | 인증 코드 발급 → 서버 mTLS 교환으로 확인 |
| "이미지 즉시 폐기" 표현이 사실과 다를 수 있다 (AI 제공사 보관 정책) | 높음 | "우리 서버에 저장하지 않음"으로 정확히 쓰고 제공사 조건 확인 |
| 분석 결과를 서버 DB에 저장하려던 설계 | 중간 | 기기 저장으로 변경. 서버에는 횟수만 |
| `getDeclaredAgeRange`로 연령 제한 | 중간 | iOS 26 전용이라 불가. 계획에서 제거 |
| 응답 시간을 5~15초로 가정 | 중간 | 가정 삭제, 스트리밍 + 실측으로 대체 |
| AI 1회 비용이 광고 수익보다 클 수 있다 | 높음 | 비용표 추가, 실측 후 모델·무료 횟수 결정 |
| 콘솔 등록을 마지막 단계에 둠 | 중간 | A단계로 이동 (appName 일치 필요) |
| 결과 공유를 링크로 하려면 서버에 결과 저장 필요 | 중간 | 1단계는 앱 링크 공유만 |
| 캡처 속 문장이 AI 지시로 작동할 위험, AI 거절 응답 | 낮음 | 프롬프트 구분, 거절 처리 추가 |
| mTLS를 쓸 수 있는 서버리스 런타임인지 미확인 | 미확인 | C단계에서 검증 |
| 자체 웹폰트 허용 여부가 토스 문서에 없음 | 미확인 | 대체 가능하게 구현 |

### 사용성

| 발견 | 조치 |
| --- | --- |
| 기다린 뒤에 "화자 확인" 화면이 한 번 더 막는다 | 제거. A/B 중립 분석 + 결과에서 뒤집기 |
| 캡처 5장은 실제 다툼 길이에 부족 | 10장으로 확대, 긴 캡처 자동 분할 |
| 캡처만으로는 배경을 몰라 엉뚱한 판정이 나온다 | 선택 입력 "상황 한 줄" 추가 |
| 결과에서 가장 쓸모 있는 "보낼 문장"이 맨 아래 | 요약 바로 다음으로 이동, 근거는 접기 |
| 처음 온 사람은 사적인 대화를 올리기 망설인다 | 예시 체험, 처리 방식 고지를 업로드 버튼 옆에 |
| 결과가 틀렸을 때 할 수 있는 게 없다 | `결과가 이상해요`, 나/상대 바꾸기 |
| 탭이 1개뿐이면 탭바 규칙(최소 2개) 위반 | 홈·기록 2개로 시작 |

### 가치·사업성

| 발견 | 조치 |
| --- | --- |
| 메신저 싸움은 가끔 일어나 재방문 이유가 약하다 | 2단계를 "답장 다듬기"로 변경 (평소에도 사용) |
| 판정만으로는 범용 AI 챗봇과 차별이 약하다 | 구조화된 결과 + 답장 다듬기 + 연습으로 차별점 명시 |
| 한쪽 캡처만 보는 판정은 신뢰도 한계가 있다 | 한계 표시, 3단계 "같이 보기"로 보완 |
| 대상을 부부로만 잡으면 토스 주 사용층과 어긋난다 | 연인까지 포함 |
| "상대 잘못 모으기"가 단독 2단계가 될 만큼 강한가 | 자동으로 쌓이는 부가 기능으로 낮춤 |
| 성공을 판단할 기준이 없었다 | 9장 성공 기준 추가 |
